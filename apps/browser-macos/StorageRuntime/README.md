# Native website-storage runtime

Swift6/macOS26.0 local package consumed by the existing AppKit app. `BrowserNativeStorage` implements the existing BrowserPorts using public WebKit APIs; it imports the exact Domain/Core/Persistence targets from the WS-F0 package without copying them or linking fake providers into the app.

Normal startup now wires the guarded `ProtectedCatalog`, native Keychain broker, Core permission/security policy and AppKit lifecycle integration. It creates no website store/view or key automatically. Persistent profile operations remain unavailable under D2A-01 and signing/key prerequisites. Qualification uses the existing synthetic memory catalog/journal between actual app processes; it is not a replacement product database.

See [architecture](../../../docs/architecture/phase-5/reports/M1/m1-wsf1-native-webkit-architecture.md), [qualification plan](../../../docs/architecture/phase-5/reports/M1/m1-wsf1-qualification-plan.md) and [actual results](../../../docs/architecture/phase-5/reports/M1/m1-wsf1-qualification-results.md). Native results are never inferred from contract/fake tests or a26.0 deployment target. Run the existing app's `storage-*` Nx targets with a registered evidence directory; do not launch against personal profiles.

[WS-F2 closeout](../../../docs/architecture/phase-5/reports/M1/m1-wsf2-closeout.md) and [results](../../../docs/architecture/phase-5/reports/M1/m1-wsf2-qualification-results.md) govern the current security/storage additions. Actual Keychain calls preserve the specified userPresence/data-protection policy; -34018 under the ad-hoc test identity is blocked, not a successful key lifecycle. Native encrypted backup framing/files are qualified only with synthetic records and a memory-only recovery authority; no production snapshot/import or recovery-custody readiness follows. The macOS27-only geolocation denial delegate is availability-guarded;26.0/latest26.x runtime qualification remains deferred, not passed.
