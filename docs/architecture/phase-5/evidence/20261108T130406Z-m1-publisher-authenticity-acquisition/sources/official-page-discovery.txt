L6: # Verify SQLCipher
L7: 
L8: All SQLCipher binary packages prepared by Zetetic are provided with a digital signature in order to verify the authenticity of a downloaded package. Below are the steps to 【5†setup】 your environment, 【6†obtain】 the Zetetic Software public key and 【7†verify】 any packages you have acquired with their corresponding signatures.
L9: ## Prepare Environment
L10: 
L11: The steps below will describe the usage of 【8†GnuPG†www.gnupg.org】 (i.e. `gpg`), a free implementation of the OpenPGP standard. If you already have GnuPG installed on your host machine, please skip to the next 【6†step】. Depending on your operating system there are a few options available for installing a GnuPG implementation. We recommend the following:
L12: 
L13:   * OS X - 【9†GPGTools†gpgtools.org】
L14:   * Windows - 【10†Gpg4win†www.gpg4win.org】
L15: If you are running within a Linux environment, your distribution may already include a prebuilt version, if not, consult your package manager for specific installation instructions. To verify your installation on your machine, run the following command from your terminal — it should display the current version of the `gpg` tool:
L16: 
L17: gpg --version
L18: ## Acquire Zetetic Software Key
L19: 
L20: There are few ways to acquire the signing key, we will cover downloading and verifying the fingerprint of our key directly from S3 first.
L21: 
L22: 【11†Download Zetetic Signing Key】
L23: 
L24: Before you import the key into your keyring, you should first verify the fingerprint of the key with the following command:
L25: 
L26:     `gpg --keyid-format 0xlong --with-fingerprint support_zetetic_net_public_key.gpg`
L27: This should print the following information, please verify the fingerprint matches:
L28: 
L29:     pub   rsa4096/0xD1FA3A2A97ED25C2 2014-04-22 [C] [expires: 2027-08-02]
L30:           Key fingerprint = D83F 5F9E B811 D6E6 B4A0  D9C5 D1FA 3A2A 97ED 25C2
L31:     uid                   [ unknown] Zetetic LLC <support@zetetic.net>
L32:     sub   rsa3072/0x0CB99EE267FD0322 2014-04-22 [S] [expires: 2027-08-02]
L33:     sub   rsa3072/0x3A7D809DD4DFEDA7 2014-04-22 [E] [expires: 2027-08-02]

L17: # REST API endpoints for repository attestations
L18: 
L19: Use the REST API to manage repository attestations.
L20: ## 【3†Create an attestation】
L21: 
L22: Store an artifact attestation and associate it with a repository.
L23: 
L24: The authenticated user must have write permission to the repository and, if using a fine-grained access token, the `attestations:write` permission is required.
L25: 
L26: Artifact attestations are meant to be created using the 【4†attest action†github.com】. For more information, see our guide on 【5†using artifact attestations to establish a build's provenance】.
L27: ### 【6†Fine-grained access tokens for "Create an attestation"】
L28: 
L29: This endpoint works with the following fine-grained token types:
L30: 
L31:   * 【7†GitHub App user access tokens】
L32:   * 【8†GitHub App installation access tokens】
L33:   * 【9†Fine-grained personal access tokens】
L34: 
L35: The fine-grained token must have the following permission set:
L36: 
L37:   * "Attestations" repository permissions (write)
L38: ### 【10†Parameters for "Create an attestation"】
L39: Headers
L40: `accept` string Setting to `application/vnd.github+json` is recommended.
L41: Path parameters
L42: `owner` string Required The account owner of the repository. The name is not case sensitive.
L43: `repo` string Required The name of the repository without the `.git` extension. The name is not case sensitive.
L44: Body parameters
L45: `bundle` object Required The attestation's Sigstore Bundle. Refer to the 【11†Sigstore Bundle Specification†github.com】 for more information.
L46: Properties of `bundle`
L47: `mediaType` string
L48: `verificationMaterial` object
L49: `dsseEnvelope` object
L50: ### 【12†HTTP response status codes for "Create an attestation"】
L51: 
L52: Status code  | Description
L53: --- | ---
L54: `201`  | Created
L55: `403`  | Forbidden
L56: `422`  | Validation failed, or the endpoint has been spammed.
