## Scope to decide

Recommend a finite **I1 + I2 + synthetic fixture-only I3** proof from the [existing M1 plan](m1-implementation-plan.md), under the [owner decision packet](m1-owner-decision-packet.md). This document contains no execution approval. A later explicit owner instruction can settle the required choices and authorize this exact slice together; do not request duplicate approval once it is actually granted.

It must not be reported as full M1 or complete browser acceptance.

## Execution sequence and test plan

After explicit authorization: verify the then-current Git state, preserve user changes, record selected decisions/scope, establish I1 package/ports, implement I2 against fakes, then add synthetic I3 and its actor/store reconciliation. Do not wire the package into M0 startup. Do not add I4+ work to make a proof look like a browser. Use ordinary constructors, not a generalized plugin runtime.

Tests must exercise invariants/failures, not mirror getters. All fixture DB artifacts are in a unique test-owned temporary root; cleanup only that root after evidence required for a failure has been retained. Test code cannot silently fall back to a browser container. No actual encryption key is created or fetched; a fake key-unavailable error can test refusal semantics only, never encryption qualification.

Use the future package's actual resolved Nx targets. Record compilation/layering, domain/fake runtime and controlled SQLite fixture checks once per relevant revision. Retry after a failure only for a recorded fix or new diagnostic hypothesis. Do not run the Phase3 suite, real-site/media workflows, native UI loops, power-loss experiments or performance qualification as part of this slice. Injected errors must be labeled; a controlled transaction/reopen is not a host-crash or hardware-durability proof.

## Exit criteria and stop

1. The selected package builds with the recorded host/toolchain and declared26.0 minimum; dependencies are engine/UI/store independent as specified. No newer-host build counts as macOS26 runtime evidence.
2. Selected S01-S12 concrete cases have honest individual results and evidence; no unresolved ownership/private-persistence/unauthorized-action defect or false commit/cleanup success remains in the proof.
3. Storage touches only controlled synthetic fixtures; actual/false-injected failures are distinguished; transaction/version/receipt outcomes survive the declared reopen cases. No real-data, production crash, encryption or full migration qualification is claimed.
4. M0 and existing source/configuration/locks/historical evidence outside the authorized new package/Nx integration remain preserved; new dependencies/frameworks absent; no unrelated process/data touched.
5. Report the finite slice as Passed, Partial or Blocked against its scoped criteria and record limitations/new issues. Even a Passed slice leaves the broader M1 implementation **incomplete** until its remaining agreed outcomes have evidence. It never completes M2 or qualifies a release.
6. Stop after the slice report; seek a new scoped instruction for any follow-up beyond the actual authorization. Do not start real-data features because fixture tests pass or silently accept ADRs.
