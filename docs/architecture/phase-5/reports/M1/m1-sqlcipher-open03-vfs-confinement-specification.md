# M1 OPEN-03 · Brokered VFS and filesystem confinement specification

Version 1.0 — Proposed, 2026-11-09. **Partially resolved design; no VFS is implemented or qualified.** [Primary review](m1-sqlcipher-critical-safety-contracts-phase2a.md) · [Write fence](m1-sqlcipher-open02-write-fence-specification.md) · [Protocol](m1-sqlcipher-open04-open05-protocol-and-recovery-specification.md).

## 1. Boundary and trade-off

Propose a custom VFS using the public `sqlite3_vfs`/`sqlite3_io_methods` surface and a dedicated ResourceBroker channel. Do not cast or patch SQLite's private Unix file structures, delegate attacker-controlled pathname opens, intercept crypto/pager internals or depend on Linux-only openat2. [SQLite VFS object](https://sqlite.org/c3ref/vfs.html) and [file methods](https://sqlite.org/c3ref/io_methods.html) define the public boundary.

After separately authorized provider initialization, register the reviewed VFS as the worker default and pass its exact name on every allowed open; forbid replacement/unregistration and alternate VFS selection while active. Provider-internal opens must be source-audited and still reach this route; migration/profiling/extension APIs that bypass it are disallowed. No private Unix-file cast or delegation is introduced. All persistent DB-related operations on this route are synchronous bounded broker RPCs. The worker has no real root path, DB FD, directory FD, writable persistent mmap or replace/unlink primitive. The supervisor broker holds descriptors and enforces the auth/lease/operation phase for every request. Complexity and IPC overhead are explicit costs; this is a qualification design, not a production performance claim. A logging shim alone is insufficient for the required prevention and short-lived-file observation.

This is confinement of the specified trusted I/O route, not an App Sandbox. Worker/provider direct syscalls and OS services are separately audited; a compromised same-user native process is outside the existing threat model. No claim that O_RDONLY directory FDs prevent unlink/rename is made; the worker receives none, and the broker denies those operations by policy.

## 2. Root traversal and stable objects

The native controller registers a new isolated local test root whose parents are controlled for the whole lease. The controller supplies its retained creation descriptor, or the broker walks from an approved held ancestor one component at a time; it never trusts an unrestricted absolute root-path open. The broker checks root owner/type/mode and creation-receipt identity, holds the descriptor and records device/inode. Every child directory is reached one component at a time with descriptor-relative openat, O_DIRECTORY/O_NOFOLLOW/O_CLOEXEC and fstat checks. File components use no-follow/no-CREATE/no-TRUNC for existing resources and verify regular file, expected owner/mode, `st_nlink == 1`, device/inode, size and expected resource ID. Reject empty components, dot/dotdot, absolute names, embedded NUL, separators in component tokens, device nodes, FIFOs, sockets, cross-device traversal and unresolved aliases. These names are generated by the broker from its manifest, never supplied as arbitrary worker paths.

Installed SDK declarations for openat/fstatat and the flags are captured in [SDK evidence](../../evidence/20261108T193319Z-m1-critical-safety-contracts-phase2a/sources/sdk-declarations.json). Declaration availability is not runtime filesystem qualification. Use the established APIs available before macOS 26; do not introduce the SDK's newer authenticated-open APIs as an assumed requirement.

Pin existing objects with held FDs throughout auth and operations. A subsequent pathname replacement cannot redirect pread/pwrite on those FDs. Before opening paired RO/RW descriptors, compare both fstat identities and link counts against the retained manifest; any mismatch closes reservations and quarantines. Do not use a readlink/realpath precheck followed by an unrestricted full-path open. Descriptors, not a pathname hash or inode number alone, carry live object identity; a restarted process cannot reconstruct that authority from a reused inode.

A path/parent renamed after pinning is a namespace discrepancy, even if old FDs still reach the original object. Check the descriptor-relative entry against the held object before grant/new sidecar reservation; a discrepancy blocks namespace work and quarantines. This prevents redirected file-content writes through the broker. It does **not** provide an atomic conditional unlink/rename against a malicious concurrent directory writer. Therefore the initial scope has no automatic original replacement/deletion/promotion and requires exclusive controlled namespace ownership. Observed outside mutation invalidates the scope. Such adversarial OS-level protection would need a separate stronger boundary.

## 3. Main file, sidecars and virtual filenames

One bundle registry maps `(run, scope, store, lease, resource UUID, artifact kind, object generation)` to held objects, permitted operation classes and expected existence. Main, WAL, rollback journal and source SHM get distinct resource UUIDs and identities. “main-wal belongs to this main” is proven by the registered bundle and controlled creation lifecycle, not suffix alone. Existing sidecars must be opened and checked relative to the same held parent. Unknown/super-journal participants cause refusal.

The VFS sees only canonical virtual names `/vx2/<run-hex>/<store-hex>/main` and recognized `-wal`/`-journal` derivatives. These names are identifiers, never passed to OS open. xFullPathname accepts the exact canonical grammar, enforces its output bound and returns it without filesystem traversal. Reject file: URIs, query parameters, alternative VFS, mixed case/encoding aliases and arbitrary ATTACH. Map a derivative through the registered main/bundle, not by accepting an arbitrary suffix string.

A new create uses a separate manifest reservation: generate an unguessable operation-owned child name, use exclusive O_CREAT|O_EXCL|O_NOFOLLOW creation with 0600 under a 0700 directory, retain the resulting descriptor and record durable intent. Refuse every pre-existing entry, including zero-length files. Pre-auth existing-store requests cannot invoke this route. Failed/unpublished creations remain quarantined, never adopted on restart by pathname.

## 4. File methods, locks and mappings

| Surface | Proposed implementation contract |
|---|---|
| xOpen | Resolve only registered virtual resource and artifact kind/phase; return an opaque handle ID; partial failure sets pMethods NULL unless xClose can safely retire the registered partial object |
| xRead | Broker pread on held RO FD; exact offset/count/phase bounds; genuine short read zero-fills remainder and returns SQLITE_IOERR_SHORT_READ; never fabricate a nonexistent header |
| xWrite / xTruncate / xDelete | Broker mutation check before syscall; deny pre-auth; after grant restrict exact artifact/recipe and lease. Never unlink original resources automatically |
| xSync | Respect sync flags through reviewed fsync/F_FULLFSYNC mapping; propagate unsupported/failure. No fake durable success or hidden dirty source flush pre-auth |
| xFileSize / xAccess | Descriptor metadata/registered existence; no broad disk search and no false “absent” to suppress recovery |
| xLock / xUnlock / xCheckReservedLock | Implement documented SQLite lock states and contention truthfully within the exclusive broker registry, including same-worker handles. Do not delegate half a lock protocol or lie that a competing writer is absent. Multi-process/external SQLite users are unsupported in the first mode |
| xFileControl | Closed allowlist. HAS_MOVED reflects held versus registered identity; SIZE_HINT cannot allocate/truncate pre-auth. For this preservation mode, PERSIST_WAL is a memory-only VFS property fixed to1 and checked through its public file-control getter; disabling it is rejected. Unknown optional controls return SQLITE_NOTFOUND; a required behavior missing blocks the configuration |
| xSectorSize / xDeviceCharacteristics | Conservative values from a reviewed backend contract; claim no atomic-write, immutable or powersafe-overwrite capability without platform evidence |
| xFetch / xUnfetch | Disable content mmap: return OK with NULL fetch pointer and valid unfetch no-op bookkeeping, with no underlying mapping; mmap_size 0 is corroborating configuration |
| xShmMap | RAM-only shared region table per main object/lease; zeroed fixed 32768-byte regions, stable aligned addresses, bounded region index/count, consistent pointers across allowed handles; no original SHM FD or disk mapping |
| xShmLock / Barrier / Unmap | Implement SQLite shared/exclusive lock-bit semantics, memory ordering and reference counts; conflict returns BUSY, not success. deleteFlag releases RAM only and never unlinks source SHM |
| xRandomness / time / sleep | Native nonstorage services with checked sizes; bounded sleep returns actual elapsed time; no key bytes/logging. They do not authorize file access |
| xDl* / syscall replacement | No dynamic loading or runtime syscall replacement; report unavailable through documented surface |

The RAM index is valid only if all participating SQLite handles use this one worker's region/lock table and no external process accesses the bundle. The first ordinary mode permits one connection. E04's live multi-handle workload and later maintenance copies need a reviewed multi-handle extension, not an invented second concurrent owner. Void callbacks such as xShmBarrier cannot return an I/O error: on tracing/broker failure they must latch a fatal coverage flag, fence broker writes and public results, request interruption and make the next returnable callback fail. They cannot silently acknowledge a complete trace or allow DatabaseReady. Pinned wal.c:806–838 maps through xShmMap; :1422–1635 reads WAL and builds wal-index memory; :2775–2836 distinguishes read-only SHM recovery failures (S07). This motivates the candidate; it does not prove compatible runtime recovery or correct lock implementation.

Pinned wal.c:2585–2640 (S14) can checkpoint and then delete WAL on close; PERSIST_WAL=1 prevents that automatic unlink, **not the preceding checkpoint**. The pre-auth broker fence must still reject checkpoint/truncate requests even during close, reporting incomplete cleanup if necessary. Normal post-auth close requires its explicit quiesced checkpoint/reconciliation grant; retained WAL and source SHM are reported residual artifacts, not falsely labeled deleted. This proposed file-control behavior is unvalidated and does not weaken required durability. An existing persistent source SHM is retained and never treated as the working index. RAM bytes can change without xWrite because SQLite holds pointers; therefore do not claim per-byte RAM write tracing. Observe allocation/map/lock/barrier/unmap lifecycle and snapshot/hash only at safe quiescent barriers. The enforceable claim is **no persistent mapping**, not complete observation of every RAM store. If SQLite requires a persistent mapping or the RAM lock/index semantics are unproven, reject the WAL mode. Original E05 disk-SHM inspection is not automatically satisfied by this RAM variant; preserve the original case and review its exact applicable oracle before execution.

## 5. Temporary, unnamed, scratch and direct-I/O handling

TEMP_STORE=3 and memory temp configuration remain required but are not the enforcement. xOpen with NULL name or TEMP_DB/TEMP_JOURNAL/SUBJOURNAL/TRANSIENT flags receives a bounded RAM object only when the recipe permits it; otherwise reject. DELETEONCLOSE does not license disk creation. RAM object size/count belongs in the finite run manifest; exceeding it returns a typed memory/full failure, never a disk fallback. Super-journals across resources are unsupported until an explicit same-scope protocol exists.

Named provider scratch, raw backup/copy destinations, VACUUM staging and any extra DB-related file are denied unless separately registered by a later reviewed operation contract. Original R09–R12/VACUUM cases cannot pass simply because these paths were refused. SQLCipher public backup APIs may be investigated later, without raw live-file copying or plaintext ATTACH/export fallback.

Pinned sqlcipher.c includes direct `fopen` log/profile paths and Apple os_log output; crypto_cc.c uses SecRandomCopyBytes and system crypto. SQLite VFS cannot intercept all of these or OS swap/crash artifacts. Disable/reject SQL profiling/file logging interfaces in the executor, review default device logging before secrets, and corroborate actual system I/O under a separately authorized run. Unknown direct filesystem writes block qualification even if every VFS trace looks clean. A grep/source audit is coverage evidence, not proof of no transitive system-library I/O. OPEN-07 remains pending, with no host log/crash configuration changed.

## 6. Complete trace contract and pressure behavior

Broker assigns strictly increasing run-global I/O ordinals. Each registered operation emits a begin record **before** syscall dispatch and one completion record with result code, returned byte count and object generation. Include full opaque context, request/operation UUID, artifact ID/kind, phase/grant epoch, offset/count/flags and bounded numeric errors. No raw file contents, SQL, pointer, key or path in records. Record denied requests with no syscall; record mapping lifecycle separately from RAM byte changes. A begin without completion after crash is Unknown, never an absent operation.

Persist audit admission/grant boundaries before allowing effects; stream high-rate events through a bounded queue with continuous draining. Reserve capacity for a complete begin/end pair and terminal stop before dispatch. On exhausted capacity, trace loss, unexpected sequence, disconnected sink or flush failure, deny new operations, fence the worker, retain sources and mark coverage incomplete. Do not drop/summarize events, wrap counters or proceed silently. If an already-running syscall completes after sink failure, its result is uncertain until independent reconciliation; no clean PASS.

Independent evidence: deterministic public-marker detector controls on permitted artifact classes, final quiescent object inventory/hashes, system-level I/O corroboration and source-to-call audit. All read/hash operations obey OPEN-01; no pre-key whole-file copy/hash is authorized. Marker absence alone cannot prove confidentiality. Finite trace bytes, record count, storage and elapsed-time bounds must be frozen per run before runtime authorization.

## 7. Guarantees versus assumptions and validation

**Enforceable proposed guarantees within the trusted route:** no mutation RPC dispatch without current auth/grant; no protected FD or persistent mapping in the worker; existing content addressed through pinned broker FDs; unknown names/artifacts denied; pre-auth original namespace unchanged by this broker; trace pressure fails closed.

**Not yet demonstrated:** correctness of the custom VFS, RAM-index WAL reading, lock/sync/durability behavior, crash cleanup, all non-VFS I/O and supported-filesystem limits. **Not claimed:** arbitrary native-code syscall confinement, hostile same-user TOCTOU immunity, secure physical erasure, all-copy forensic privacy or release sandbox qualification.

Before first DB open, require approved OPEN-01 disposition, pure-policy/malformed-RPC checks, real filesystem-backend negative/race checks on ordinary non-DB synthetic files, VFS contract validation, no-provider observer/detector controls and a scoped system-I/O/diagnostics plan. Those are future separately authorized activities, not Phase 2A execution. A minimum fresh DELETE-journal store may be considered before WAL only after all relevant gates; WAL remains blocked until its own RAM-index proof.

**No VFS, broker, adapter or test fixture was implemented; no provider or runtime test was executed.**
