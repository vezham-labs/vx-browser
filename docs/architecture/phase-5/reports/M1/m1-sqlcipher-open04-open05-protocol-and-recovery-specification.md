# M1 OPEN-04/05 · IPC v2, outcomes and durable recovery

Version 1.0 — Proposed, 2026-11-09. **Design only. No protocol, broker or journal is implemented here.** [Primary review](m1-sqlcipher-critical-safety-contracts-phase2a.md) · [Write fence](m1-sqlcipher-open02-write-fence-specification.md) · [VFS](m1-sqlcipher-open03-vfs-confinement-specification.md).

## 1. Scope and process model

Preserve Phase 1 v1 source and its fake-only 113-byte control/133-byte key baseline. The v2 endpoint is separate and must not reinterpret v1 `ProtocolReady` as authentication. Use one DB executor per worker, a control loop, and a separately serviced broker RPC channel in the supervisor. Never wait for FS RPC while holding the supervisor's control/retirement lock; the broker cannot depend on the DB executor processing another control message.

Proposed inherited sockets: FD 198 control, 199 one-shot key, 197 broker. Stdout/stderr go to bounded continuously drained diagnostic pipes, never protocol. No protected file/directory FDs are inherited or sent via SCM_RIGHTS. A registered static executable with pinned hash is launched with close-on-exec defaults, minimal environment and no key in argv/env. Private/foreign/stale scopes are rejected in native admission **before launching the real image**, whose finalizers can call provider code even without explicit SQL calls.

All following formats are proposed wire contracts for design review, not generated source. Real-provider launch, fake execution, new file I/O and every runtime phase still require separate authority.

## 2. Control framing, identity and negotiation

All integers unsigned big-endian unless explicitly signed; UUIDs are exactly 16 raw bytes, never shortened/stringified. A stream frame starts with a 4-byte body length, excluding that prefix. Body length is 145..4096 and must equal 145 + payload_length. Reject oversize/underflow, nonzero reserved fields, unknown enums/flags, trailing data and malformed frames before allocation. Read exact lengths under an assembly deadline; EOF mid-frame is failure, not a request.

| Byte offset in body | Width | Field |
|---|---|---|
| 0 | 4 | magic ASCII VXW2 |
| 4 | 2 | protocol version 2 |
| 6 | 2 | opcode |
| 8 | 77 | Phase 1 context layout: run UUID16, worker UUID16, scope kind1, scope UUID16, store UUID16, lease generation8, DEK version4 |
| 85 | 16 | full operation UUID |
| 101 | 8 | per-direction sequence, starts 1, strict increment, no wrap |
| 109 | 8 | reply_to sequence; zero for requests, originating request for responses/events |
| 117 | 16 | resource UUID; zero only for session-level HELLO/INIT/SHUTDOWN before binding |
| 133 | 8 | deadline in continuous monotonic nanoseconds since boot |
| 141 | 4 | payload length |
| 145 | variable | opcode-specific payload |

Context scope kind remains 0 catalog, 1 persistent, 2 private; private is rejected before any persistent/native provider authority. All context UUIDs, operation UUIDs, lease and DEK version must be nonzero and match native admission. Resource UUID and object generation come from the broker manifest. Connection identity is `(run,worker,resource,lease)` in this one-connection protocol; no connection reassignment or second-connection ambiguity.

HELLO is the only permitted initial message, with min_version u16=2, max_version u16=2 and required_features u32. Feature bits: 0 full UUID, 1 separated auth/grant, 2 broker I/O, 3 durable quarantine, 4 independent outcome/cleanup; all five required, unknown bits rejected. HELLO_ACK returns the selected u16, zero reserved u16, feature mask u32, executable SHA25632 and link-manifest SHA25632 after the common response prefix. Supervisor compares against its own prelaunch hashes; peer-reported hashes are not independent attestation. v1/no-common-version fails with no downgrade and no key/path/provider initialization.

Deadline conversion uses checked `mach_continuous_time`/timebase arithmetic on the same Mac; no wall-clock comparison or overflow. Replies carry the originating deadline and may be parsed for internal reconciliation after expiry, but cannot publish sensitive results to a retired generation. Finite per-stage deadlines are mandatory run-manifest fields; Phase 1's 500 ms partial-frame and 2.5 s startup values may be used only for a separately approved fake conformance run. Real provider time budgets need reviewed supported-platform evidence, not invented timing acceptance.

## 3. Requests, responses and exact payloads

Every response starts with a **24-byte result prefix**: status u16, worker_state u16, outcome u8, cleanup u8, flags u16, SQLite primary i32, SQLite extended i32, revision u64. Native/protocol failures without a SQLite call use zero numeric SQLite fields. Revision is 0..2^63−1, or UINT64_MAX for unknown/not applicable. flags bit0 means cancellation intent accepted; all other bits zero. outcome: 0 NotApplicable, 1 NotStarted, 2 NotCommitted, 3 Committed, 4 Unknown. cleanup: 0 NotAssessed, 1 Confirmed, 2 Incomplete, 3 Quarantined. Neither field is derived from the other.

Status values: 0 OK, 1 InvalidInput, 2 InvalidOwner, 3 InvalidState, 4 Unsupported, 5 UnauthenticatedOrCorrupt, 6 IdentityMismatch, 7 Busy, 8 StorageIOFailure, 9 StorageFull, 10 ResourceLimit, 11 Cancelled, 12 Deadline, 13 ProviderFailure, 14 RecoveryRequired, 15 ProtocolFailure, 16 TraceIncomplete. These normalize Phase 2's coarse error classes; raw error strings/SQL never cross the boundary.

Worker-state wire values: 0 Boot, 1 Negotiated, 2 Initializing, 3 Initialized, 4 AwaitKey, 5 KeyValidated, 6 Opening, 7 KeyApplied, 8 Authenticating, 9 AuthenticatedReadOnly, 10 Writable, 11 Busy, 12 Fenced, 13 Closing, 14 Closed, 15 Quarantined, 16 CreateSettingsReady, 17 CreateUnpublished, 18 ConfiguredAwaitRead. Invalid transition is terminal protocol failure, not a reset.

| Request opcode | Exact payload / semantics | Responses (all have result prefix) |
|---|---|---|
| 0x0001 HELLO | 8 bytes as §2 | 0x0101 HELLO_ACK: prefix + 72 bytes as §2 |
| 0x0002 INIT | Empty; once only, no DB/key | 0x0102 INIT_READY: prefix + identity-manifest digest32 |
| 0x0003 PREPARE | mode u8 (0 existing,1 exclusive-new), reserved3 zero, object_generation u64, expected_revision u64, expected_identity digest32, expected_settings digest32, run_manifest digest32; total116 | 0x0103 PREPARE_ACK: prefix only; validation of opaque values only, no path/file effect; enters AwaitKey |
| 0x0004 AUTHENTICATE | Empty, same opening operation UUID as PREPARE; only after complete key+EOF | 0x0104 KEY_APPLIED: prefix only; then 0x010E SUITE_CONFIGURED: prefix + settings digest32 and wait in ConfiguredAwaitRead. For new mode, 0x010D CREATE_SETTINGS_READY: prefix + settings digest32 instead |
| 0x000B AUTH_READ_GRANT | settings witness digest32, post-key baseline witness digest32, read_epoch u64; total72. Supervisor installs the broker read epoch first; same opening UUID | 0x0105 AUTHENTICATED: prefix + object_generation u64 + identity digest32 + settings digest32 + full-oracle digest32 (104 bytes after prefix) |
| 0x0009 WRITE_GRANT | grant_kind u8 (0 existing normal,1 new initialize), reserved7 zero, grant_epoch u64, witness digest32; total48. Broker grant installed independently by supervisor first | 0x0106 DATABASE_READY: prefix + grant_epoch u64 + verified full-settings digest32 for existing, only after operational configuration/readback. New initialization instead returns 0x010C CREATE_RESULT: prefix + identity digest32 + committed revision u64 and remains unpublished |
| 0x0005 EXECUTE | mutation UUID16, expected revision u64, recipe kind u16, reserved u16=0, item count u32, public payload digest32, registered recipe UUID16; total80. No arbitrary SQL/rows/paths. Recipe and expected public data must already be in immutable run manifest | 0x0107 ACCEPTED: prefix only; 0x0108 OP_FINAL: prefix + mutation UUID16 + payload digest32 + full-state/oracle digest32 |
| 0x000A RECONCILE | mutation UUID16, original expected revision u64, original payload digest32; total56; read-only lookup, no replay | 0x0108 OP_FINAL with the same 80-byte receipt/oracle suffix; absence follows §6, not automatic NotCommitted |
| 0x0006 CANCEL | target operation UUID16; cancel request has its own UUID | 0x0109 CANCEL_ACK: prefix + target UUID16; intent only. Target operation later has one OP_FINAL or remains Unknown on loss |
| 0x0007 QUIESCE_CLOSE | Empty; no new work; fence ingress/results, settle admitted op under manifest's reconciliation rule | 0x010A CLOSE_RESULT: prefix + cleanup mask u32 + unresolved resource count u32 |
| 0x0008 SHUTDOWN | Empty; only after Closed or poisoned no-handle terminal state | 0x010B SHUTDOWN_RESULT: prefix only; provider return and process exit remain separate witnesses |
| Any rejected request | No recovery by guessing field meaning; framing/context fatal errors close channel | 0x01FF REJECTED: prefix only when safely frameable; otherwise fail channel without raw diagnostics |

Exact fixed suffix lengths are checked; duplicate/missing responses or mismatched reply_to/op/resource/context fail closed. Multi-response AUTH/EXECUTE events use increasing sender sequence and the same originating request reference. Each distinct logical operation has a new full UUID; PREPARE/AUTH/AUTH_READ_GRANT/WRITE_GRANT share the opening UUID only as specified. Retired IDs cannot be reused. At most one opening/DB operation active; at most64 admitted DB operations and128 total control operations per worker, then orderly retirement. A later maintenance protocol cannot be smuggled into reserved bits/recipe kinds.

## 4. One-shot key and broker frames

**Key:** exactly133 bytes then EOF, no length prefix: VXK2 magic4, version u16=2, context77, opening operation UUID16, key_length u16=32, key32. Layout preserves Phase 1 field widths, not v1 endpoint semantics. PREPARE binds its resource/object generation; any mismatch, early key before INIT/PREPARE_ACK, extra bytes, timeout or missing EOF rejects/wipes without file access. Hold a single owned key buffer through the checked `sqlite3_key(...,32)` return; wipe on all terminal paths. No C-string/hex/URI key conversion. Provider-owned copies retire with real close; memory/register/kernel/OS erasure is not guaranteed.

**Broker RPC:** separate stream, prefix u32 body length; header177 bytes, max body65536, max data chunk32768. Offsets: magic VXF2 at0/4; version2 at4/2; opcode at6/2; context at8/77; request UUID at85/16; parent transport-operation UUID at101/16; sequence at117/8; resource UUID at125/16; opaque handle ID at141/8; authority/grant epoch at149/8; offset at157/8; count at165/4; flags at169/4; payload_length at173/4; payload at177. Sequence starts1/increments; one outstanding request per DB executor; response echoes UUID/sequence, sets opcode high bit and prepends result i32 plus extended/native code i32 to its data. Unknown/oversize/extra-FD messages fail closed.

Broker opcodes:1 OPEN (flags/artifact encoded in flags, no path; returns handle u64),2 READ (no request payload; response count bytes or genuine short-read data),3 WRITE (payload exactly count),4 TRUNCATE (offset is requested length),5 SYNC,6 CLOSE,7 SIZE (response u64),8 LOCK,9 UNLOCK,10 ACCESS (response u32 boolean),11 DELETE,12 SHM_EVENT,13 FILE_CONTROL. Non-data requests have count0/payload0; responses do not invent result bytes. READ/WRITE offsets and sizes are overflow-checked against manifest/resource bounds. The parent operation UUID must match the broker's currently admitted opening/EXECUTE/close operation and its explicit authority epoch; each I/O request UUID is separately unique. Bind it to the active operation before dispatch and retain that binding for trace/completion, even after cancellation. Epoch0 permits only the approved pre-key header request and configuration-only phase. AUTH_READ_GRANT installs a new read-only epoch; WRITE_GRANT installs a different write epoch. Any queued request carrying an old epoch is denied even if processed after a later grant. The broker's per-resource state, not an opcode/flag from the worker, authorizes mutation. Grant/revoke is a supervisor-local API and is **not** available as worker RPC.

Flags are a closed combination: low byte artifact kind (1 main,2 WAL,3 rollback,4 statement/super,5 RAM temp,6 RAM SHM), next byte the protocol mode below, upper16 zero. All unlisted mode/argument combinations reject; do not pass raw C enum values across the wire. VFS implementation maps these local values to reviewed pinned SQLite constants.

| Broker operation | Closed mode and argument meaning |
|---|---|
| OPEN | mode1 ReadOnly,2 LogicalReadWrite,3 ExclusiveNew; handle/offset/count0, resource must be registered; no raw paths |
| READ / WRITE | mode0; live handle, offset/count as declared; WRITE payload=count; response READ bytes cannot exceed count |
| TRUNCATE | mode0, offset=new length, count0; denied before grant |
| SYNC | mode1 Normal,2 Full,3 NormalDataOnly,4 FullDataOnly; offset/count0 |
| CLOSE / SIZE | mode0, offset/count0; SIZE returns u64; CLOSE is resource retirement, not deletion |
| LOCK | mode0 None,1 Shared,2 Reserved,3 Pending,4 Exclusive; offset/count0 |
| UNLOCK | mode0 None or1 Shared only; offset/count0 |
| ACCESS | mode0 Exists,1 Read,2 ReadWrite; handle/offset/count0; evaluates resource registry and object metadata |
| DELETE | mode0 or1 (also require directory durability); registered operation-owned namespace only; never pre-auth source |
| SHM_EVENT | mode1 Map,2 SharedLock,3 ExclusiveLock,4 UnlockShared,5 UnlockExclusive,6 Barrier,7 UnmapRetain,8 UnmapDeleteRAM. offset=region/lock-slot index; count0. Map size is fixed32768; lock span is one slot in this slice. Events describe RAM lifecycle, no persistent mapping |
| FILE_CONTROL | mode1 HasMoved (u32 response),2 SizeHint (offset=requested length; forbidden pre-auth),3 LockState (u32 response),4 PersistWal (offset UINT64_MAX=query or1=enable, u32 result1; offset0 disable is rejected in this mode). Other SQLite optional controls return NOTFOUND locally, without arbitrary broker dispatch |

All request payloads not explicitly declared for WRITE are empty. Numeric extended/native code is the SQLite extended code when one exists, otherwise a bounded native errno; it is not a raw message. Broker replies always have the two i32 result fields; OPEN/SIZE return u64, ACCESS/HasMoved/LockState return u32, READ returns its actual bytes, all other successful replies have no suffix. FILE_CONTROL mode3 returns the lock-mode wire value above; mode4 returns a memory-only property and cannot trigger file mutation. SHM_EVENT never transports a pointer; the VFS must hold its RAM table and commit the metadata event before returning a newly mapped pointer. Multi-slot lock calls decompose under one atomic local lock-table transaction and emit a deterministic ordered event for each slot; partial lock acquisition is rolled back before returning BUSY. This table freezes the single-worker protocol modes; filesystem/lock behavior still needs implementation review and validation.

The immutable RunManifestV2 is UTF-8 JSON with sorted ASCII keys, compact separators, no duplicate/unknown fields, no floats, no NaN, maximum depth8 and total size1MiB; all UUIDs/digests are lowercase fixed-width hex and counters are bounded unsigned integers. Its digest is over exact canonical bytes, not a semantic reserialization. Required fields are format_version=2, context (all77-byte fields represented individually), executable/link identity digests, root binding (opaque root ID plus dev/inode/uid/mode), resources (unique UUID, artifact kind, existing/new, expected object generation and metadata, parent resource/root ID and generated component name), expected identity/oracle digests and phased settings digests (pre-auth suite subset, pre-grant observed subset, final required configuration), recipes (UUID, kind, exact public synthetic operation and digest), permitted phases/fault ordinals, finite time/memory/file-count/byte/output/trace quotas, key-custody reference (opaque only), cleanup/preservation policy and approved execution-scope reference. Product paths, real content and key bytes are forbidden. An existing content digest is explicitly unknown until legally captured after KeyApplied; never precompute it to bypass OPEN-01. A content-digest witness is a journal event and cannot mutate the immutable manifest. Missing required quota/oracle or unapproved phase rejects the manifest. A fake-only manifest uses non-filesystem root/resource metadata; it cannot authorize a real backend.

No broker payload is logged. File data may be ciphertext or synthetic plaintext temp bytes; IPC/kernel memory is part of the trusted secret-lifetime boundary. Trace only bounded metadata. RAM methods operate locally but emit ordered metadata under the same coverage/overflow contract.

## 5. Lifecycle and authority separation

`Boot → Negotiated → Initializing → Initialized → AwaitKey → KeyValidated → Opening → KeyApplied → ConfiguredAwaitRead → Authenticating → AuthenticatedReadOnly → Writable → Busy → Writable → Fenced → Closing → Closed`. Any uncertainty enters Quarantined, never loops to Initialized on the same provider process. Invalid/private admission occurs before real launch.

For existing stores, no Opening transition under the current literal OPEN-01 constraint has a supported implementation; D2A-01 remains blocking. Under a future approved exception, the broker admits only the specified truthful header read until KeyApplied. The worker applies only reviewed non-reading suite configuration before schema/row authentication, emits SUITE_CONFIGURED and pauses. Supervisor then captures the legal post-KeyApplied/pre-auth source baseline, checks the settings witness and installs AUTH_READ_GRANT. Any setting/getter that needs an unapproved data read stays deferred or causes failure; it cannot consume the auth-read grant early. The worker begins schema/identity reads only after receiving that explicit read grant. No response means a write grant: supervisor checks witness digests, current lease/resource, trace completeness and persisted GRANT_INTENT before installing grant and sending WRITE_GRANT. A new write epoch initially authorizes only the exact opening/configuration recipe in the run manifest, including a declared journal-mode transition if needed. It does not admit normal mutations. The worker applies and reads back all remaining operational settings, then emits DATABASE_READY with the full verified-settings digest; supervisor verifies that exact final digest before admitting EXECUTE. Source-changing configuration therefore occurs only after identity authentication and a durable grant, while no application mutation is admitted on partly configured state.

For new creation, PREPARE mode1 requires an explicit fresh-create run-manifest grant. After key validation, the broker exclusively reserves a never-existing resource and permits only that initial zero-length reservation; no keyless data-page writes. AUTHENTICATE opens/binds/configures and emits CREATE_SETTINGS_READY. Supervisor verifies settings/key/resource state and installs a CreateInitialize grant, allowing only the exact new fixture's schema/identity/seed transaction. CREATE_RESULT does not establish authenticated reopen. Close/shutdown and a new worker's ordinary existing-mode authentication are mandatory before the controller can publish a valid fixture. An interrupted reservation/initialization stays unpublished/quarantined; it is never adopted merely because the name or zero length looks plausible.

The SUITE_CONFIGURED digest covers only the manifest's pre-auth suite/settings subset; AUTHENTICATED reports the observed pre-grant subset and marks any write-requiring settings pending. Neither is presented as the final configuration digest. No pre-auth getter is allowed to trigger an unapproved data read; actual I/O behavior remains a required later observation. The exact startup settings and source-derived `4.20.0 community` identity remain the Phase 2 design §7 contract; effective values remain unobserved. INIT does not run SQLCipher handle PRAGMAs. Default OS-device logging/finalizers remain separately gated; no new pre-key SQL command or key transport is authorized by this flow.

## 6. Mutation and commit semantics

Preserve [Core-to-Persistence](core-boundary-contracts.md#boundary-d--core-to-persistence): mutation, expected-revision check, new revision and receipt commit in **one DB transaction**. Keep the existing synthetic identity/state/rows/receipt schema from worker design §6, including a maximum64 retained receipts and exact public recipe digest. Its existing `fixture_receipts.operation_uuid` column stores the durable mutation UUID; transport-attempt UUIDs remain separate and do not rename or migrate the historical schema. Transport operation UUID and durable mutation UUID are distinct full16-byte fields; retries get a new transport attempt but cannot silently replay an Unknown mutation.

Persist OP_INTENT before dispatch. ACCEPTED means admitted, never committed. OP_FINAL Committed requires the provider commit result plus matching receipt/revision/complete-state oracle. Interrupted/error commit is Unknown until independently authenticated read-only reconciliation. NotCommitted is allowed only with established prior state and no matching mutation effects, not merely a missing message or CANCEL_ACK. A retained same mutation/digest returns its known receipt; changed digest rejects. RECONCILE is allowed only in AuthenticatedReadOnly or fully ready Writable with no active DB operation; it is a read-only receipt/state lookup and cannot insert a receipt or advance a revision. No new mutation is admitted while a prior outcome for the scope remains unresolved. Missing/evicted receipt or unavailable key/state stays Unknown/Conflict where absence cannot prove noncommit. No unlimited exactly-once guarantee follows from a64-row receipt window.

Supervisor journals COMMIT_OBSERVED before relaying its known result. ACK_SENT records attempted transport, not proof that Core/UI received it. A crash between DB commit and external journal/ack still reconciles through the DB receipt. A stale/retired UI generation gets no data; an internal committed outcome is still reconciled. Never convert Committed to Cancelled or Unknown to RolledBack just to complete cleanup.

## 7. Cancellation, interrupt and lock fencing

Control loop atomically fences new operation/result admission and sets a cancellation intent. Acquire a live-handle interrupt pin under a small ownership mutex, release the mutex, call sqlite3_interrupt, then retire the pin. DB executor exclusively owns prepare/step/finalize/transactions/close and waits for all interrupt pins before destruction. No lock is held across SQL or broker RPC while the control thread needs it. Progress callbacks inspect atomic deadline/cancel flags only; they do not invoke SQL, protocol or file operations.

[SQLite interrupt](https://sqlite.org/c3ref/interrupt.html) permits cross-thread interruption only while the connection remains valid, and near-complete work can still finish. CANCEL_ACK therefore means intent received. Resolve the actual commit outcome separately. Once a lock/revocation epoch advances, no old result or broker write grant can be reused; a bounded reconciliation grant may only settle the already admitted transaction as explicitly listed in the run manifest. It cannot start a new mutation, extend key access indefinitely or publish old sensitive results. Deadline exhaustion leaves CleanupRequired/Quarantined with owned resources preserved.

## 8. Durable journal and restart reconciliation

Qualification records contain only synthetic opaque metadata. Their journal/trace directory is separate from the protected source bundle; writing such non-secret control evidence is not source DB/sidecar mutation. Private context is refused before durable launch/intent records, and no private session identity or receipt is persisted. They are not product Keychain/envelope records. Use one supervisor writer, O_APPEND/no-follow to a registered0600 journal under0700 root; exact480-byte records, short/torn writes retained as corruption evidence. No automatic tail truncation or repair. A required fsync/F_FULLFSYNC failure stops launch/grant; directory creation/manifest publication durability is separately checked. Hardware-power-loss behavior remains unqualified.

Record layout (byte offsets): magic VXJ2 0/4; version2 4/2; type6/2; length8/4=480; sequence12/8; previous SHA25620/32; context52/77; transport operation129/16; mutation145/16; resource161/16; object generation177/8; grant epoch185/8; state193/2; outcome195/1; cleanup196/1; expected revision197/8; actual revision205/8; payload digest213/32; immutable run-manifest digest245/32; expected identity digest277/32; executable digest309/32; PID341/8; observed process-start token349/16; device365/8; inode373/8; source-bundle digest381/32; continuous timestamp413/8; reserved421/27=zero; record SHA256448/32 over first448 bytes. First previous digest is zero, sequence starts1. Non-applicable identity fields use zero; unknown revisions use UINT64_MAX. PID must fit a native positive pid_t; start token is the captured seconds/microseconds pair, not an authority to kill by itself.

Types:1 LAUNCH_INTENT,2 CHILD_REGISTERED,3 RESOURCE_BOUND,4 KEY_APPLIED,5 AUTH_VERIFIED,6 GRANT_INTENT,7 GRANT_INSTALLED,8 OP_INTENT,9 COMMIT_OBSERVED,10 ACK_SENT,11 REVOKED,12 CLOSE_OBSERVED,13 WORKER_EXIT,14 BROKER_RETIRED,15 QUARANTINED,16 RECONCILED,17 COMPLETE. Key bytes and raw paths/SQL are never present. Source-bundle digest is zero until OPEN-01 legally permits full hashing; zero is unknown, never a verified empty bundle.

Persist LAUNCH_INTENT before spawning; capture registered child PID/start/hash before admitting keys. Persist GRANT_INTENT before enabling any source mutation. OP_INTENT precedes operation dispatch. An existing root with a missing journal/manifest, a torn tail or an unregistered resource is an orphan/quarantine condition, never a fresh empty run. At restart validate the exact run manifest/digests/record lengths/hash chain/sequence and registered root/object metadata; any torn, unknown or inconsistent record keeps scope quarantined. A plain hash chain detects accidental alteration, not malicious rewriting. It is adequate only for the declared trusted synthetic-controller model. Production authenticated intent/bootstrap and rollback protection remain existing SPEC-04/05/12 requirements and outside this qualification format.

Do not automatically reattach to a stale worker or kill a PID from the journal. The original parent can signal its retained unreaped direct child with checked kill/wait results; a restarted supervisor cannot recreate that relationship from PID/start metadata. On broker/control EOF, the worker fences and attempts bounded exit; a blocked call may linger. Since all persistent I/O requires the dead broker, it gains no new broker-mediated writes, but in-flight syscalls and OS diagnostics still need reconciliation. Confirm old process absence through a reviewed observation or require controlled operator recovery; uncertainty denies a new lease for that scope. Other disjoint scopes need their own proven resources and grants.

After old resources are demonstrably quiescent, a fresh worker/lease reacquires the correct synthetic key from the independently held run-controller custody reference, authenticates without source writes and reconciles receipt/revision/object state. Missing key means quarantine, never regeneration over ciphertext. This is not Keychain or offline user recovery. No auto-retry, source deletion, inode-based adoption or old lease reuse. Maintenance branch/promotion recovery remains excluded until its two-key/resource protocol is separately specified.

## 9. Diagnostics, cleanup and remaining limits

Drain child stdout/stderr concurrently with control and broker service into bounded private memory. Normal raw output allowance is zero; preserve only a safe violation flag/count, not raw bytes that may contain keys/SQL. A4096-byte total detection buffer is a proposed fake-run bound, not a license to capture output or a proven provider limit. Zero/wipe owned diagnostic buffers on retirement; pipe closure/grandchild writers cannot block drain/reap indefinitely. OS unified logging and crash reports bypass those pipes and remain OPEN-07; no blanket secret-leak prevention is claimed.

CLOSE_RESULT cleanup mask bits:0 provider connection destroyed via checked sqlite3_close,1 all statements/blobs/backups retired,2 owned key/scratch buffers retired,3 VFS/RAM handles retired. These are worker observations. Supervisor adds independent checked direct-child exit/reap, broker handle/refcount retirement, durable outcome resolution and final artifact disposition. cleanup Confirmed requires all applicable witnesses, never close_v2 zombie success or exit0 alone. Outstanding cursor/BUSY/checkpoint failure/failed wait remain incomplete/quarantined. Only one supervisor wait owner may reap a child. Use bounded nonblocking wait progression and check every signal/wait return; ESRCH, ECHILD, unexpected wait error or elapsed deadline cannot be converted into a successful reap/cleanup witness. Phase 1's unconditional reaped assignment and blocking post-reap diagnostic read are findings to correct in a separately authorized v2 implementation, not changes made here. No pre-auth cleanup method gains mutation authority.

OPEN-04 is specified for this fail-closed synthetic scope. OPEN-05 remains partial for full Phase 2 because maintenance multi-handle/two-key/promotion messages remain prerequisites to that later slice. The single-worker FS mode table is specified above; its mapping to the pinned API and backend behavior remain unvalidated. R09–R12 are prohibited on this v2 single-connection slice; do not reinterpret recipe kinds to execute them. Genuine bind-failure instrumentation, device logging and finite per-case budgets/oracles remain OPEN-06/07/08. No production protocol or release claim is made.
