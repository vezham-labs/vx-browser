## Interpretation and common prerequisites

Original definitions, expected results, failure oracles, fixtures, cleanup, environment and CFG/FX/HASH/STATE/TRACE/FAULT code definitions remain in the [50-case source matrix](../../evidence/20261108T150828Z-m1-sqlcipher-runtime-readiness/synthetic-test-matrix.json). This table preserves every original ID and description. All original preconditions and original G01–G08 references apply; their historical readiness status is not asserted to be today's implementation status. The JSON retains the complete original definition beside the added design route so no case-specific prerequisite is lost.

Every row requires future explicit authority, a fixed revision/executable and owned synthetic root/key/resource manifest, exact frozen expected-state and failure oracles, finite budgets, registered-process ownership, working detectors, redacted evidence and reviewed cleanup/preservation. Any real database route additionally requires resolution of design OPEN-01, the enforced E pre-auth/identity/SHM fence, relevant A–F foundations and separate G authorization. B/F fake probes also need separate authorization; none are run here.

Preparation stages identify required features; they do not authorize those features to execute. All real-provider case execution belongs to G; H reviews results without executing EXP-03/04. Pure admission-only rows can eventually be checked with fakes in B/F. No fake route demonstrates native crypto, I/O or actual provider behavior. K13 requires real evidence if its committed-outcome reconciliation portion is claimed.

In each row the evidence column lists the original artifact codes literally. CFG/FX/HASH/STATE/TRACE are required for every case; T/R additionally require FAULT. These describe future artifacts, not files generated by this design review. Retain exact effective settings, scope/lease/operation identities, trace coverage, hashes, expected-record comparison and disposition at the relevant cutpoints. Environment remains the existing DB0 isolated provider-harness family; macOS 27.2 arm64 is discovery, minimum deployment 26.0 is not macOS 26 runtime qualification.

## Mapping reconciliation and coverage limits

- Exactly 50 unique original cases: E01–E12 (12), K01–K16 (16), T01–T10 (10), R01–R12 (12). No case is added, removed, renumbered or counted as executed.
- Six pure admission-only routes do not require SQLCipher: K05, K06, K07, K08, K09 and K14. K13 is conditional; the other 43 full case claims require actual provider execution. Fake coverage is identified per row and never substituted for the provider portion.
- K15's real bind-failure observation remains OPEN-06. A malformed frame, missing key or injected adapter error cannot prove cleanup after an internal provider allocation/codec failure.
- K14 carries the explicit correction from the prior worker-design crosswalk: **REQ-09, SPEC-03/06, AC04/14, OD-R05/06**. Its old REQ-05/06 and AC05/14 mapping remains preserved inside the original definition, not silently rewritten. The corrected route is persistence refusal only. See [Core to Persistence contract](core-boundary-contracts.md#boundary-d--core-to-persistence) and [Developer Specification](m1-developer-specification.md).
- All other original REQ/AC/SPEC/OD-R mappings, parent EXP/CRYPTO reference, G prerequisites and evidence codes are carried unchanged in the JSON. A supporting PQR route does not establish a complete AC, EXP, Keychain/profile-lock/private-engine or portable backup pass.
- Existing REQ-21 Stage C final-candidate qualification and REQ-22 WebKit-data qualification remain separate. No release or AC08 claim is made by these cases. Current OP-01–OP-04, OD-R01–OD-R20, WS01.1, historical crosswalk meanings, ADR statuses and conditional engine strategy remain unchanged.
