## 1. Scope, authorization and entry prerequisites

WKS identifiers are local supporting plan IDs. They do not replace ISO-001/PRIV-001/LOCK-001/BACKUP-003, add a canonical AC, renumber the165-row M1 matrix, change an EXP result or execute a SQLCipher PQR. Native/model/static contributions are reported separately; no model response qualifies a native positive. Reuse existing RESULT/REVIEW/CFG/FX/TRACE/STATE/FAULT/HASH/UI artifact definitions from [M1 case conventions](m1-case-level-traceability.md#matrix-conventions).

Separate explicit implementation/execution authority must identify exact source/binary/app/container identities, new fixture UUIDs, allowed cases/classes/platforms/faults, budgets, cleanup and stop conditions. This task grants none. Initial WS-F0 uses fake engine/catalog ports and no filesystem/provider/WebKit runtime. Later standalone native engine qualification can use a synthetic fake catalog so it does not depend on SQLCipher; it still cannot qualify production catalog durability/crypto or the full profile/lock/backup product.

Before any native call, resolve the preserved [EXP-01 cleanup diagnostic prerequisite](m1-exp-01-cleanup-diagnosis.md): original A/B logical states remain unknown after a removal failure/crash. A future authorized noncreating investigation must use the original valid app namespace without named-factory probing or original-data deletion. Do not launch fresh stores to bypass that recorded stop. A reviewed disposition and exact isolated new harness manifest are entry requirements; this document does not approve a retry or change the earlier prerequisite.

Native harness requires a real interactive AppKit/main-actor lifecycle, public APIs, reviewed object/reference lifetime instrumentation and asynchronous per-operation checkpoints. No default-store warmup, private API, security downgrade, TLS bypass, Keychain API, real accounts/media or uncontrolled process termination. Public WebKit calls may internally handle engine credentials/storage; future authority must explicitly cover only fresh synthetic namespace effects, not access to personal accounts or credential stores. Callbacks/timeout error handling are finite; no sleeps-as-release-proof or repetitive unchanged runs.

## 3. Case execution and outcome rules

Each case below has its own complete setup/assertions/fault/evidence fields in the JSON. The listed setup and fault are proposed actions, not actual commands run. Execute once per approved variant/platform/cutpoint with exact fixture revisions; report every instance separately. Model and native branches are separate records. Multi-cutpoint cases freeze explicit labels before execution; no hidden unbounded permutation/retry loop.

**Pass:** exact listed assertions, applicable native/class controls, current binding/generation and evidence complete; error-negative cases may pass only their error-handling assertion. **Fail:** unauthorized/wrong/default scope, cross-profile/private leak, unwanted overwrite/deletion, false lock/cleanup/durability or stale authority acceptance. **Inconclusive:** missing/unsafe observation, failed positive control, callback/trace gap, uncertain state or inaccessible declared scope. An unsupported required feature is a capability Blocked condition, not a pass. These rules apply to every row below.

Every case retains RESULT and independent REVIEW plus its listed artifacts. Record app/source/OS/WebKit/SDK/runtime and deployment target separately, class/origin/owner/operation/generation, before/after native registry and lifecycle checkpoints, call/error outcomes and cleanup disposition. Native content export/restore blobs and raw website secrets are not logs. Test-only public markers can be captured in the exact isolated evidence scope. Nil callbacks/errors, directory absence, object release counts and marker scans each have limitations; combine observations without claiming forensic completeness.

## 4. Platform, process and failure safety

Use existing D0/C0 static/model, I0 interactive engine, R0 recovery, L0 lock and X0 cross-Mac environment families. Native conditions include logged-in session, controlled origins, persistent/nonpersistent store scope and owned resources; termination only with exact safe attribution. A process may serve several views/profiles; record affected set and data/lifecycle outcomes without assuming a PID per profile. If ownership cannot be bounded, WKS-019/020 stay Blocked; fake callbacks do not prove real crash recovery.

WKS-036 checks declarations/minimum API selection only. WKS-037 is the mandatory actual macOS26.0 plus latest supported26.x qualification, kept at the owner's final-validation stage. Newer-host discovery and a26.0 deployment target do not pass that requirement. Signing/notarization, Gatekeeper/App Sandbox/Hardened Runtime and final release candidate remain mandatory independent Stage C gates; no new pass or waiver. No builds occur in this task.

Model error/timeout injection in WKS-018/027/039/040 is explicitly not proof of native OS/filesystem error behavior. Future native faults must be non-destructive, deterministic, registered and separately authorized; no engine-file edits, disk fill, personal-store deletion or permission weakening. A crash stops the affected run, preserves evidence and yields explicit uncertainty; no automatic cleanup loop or repeated retry of the original prototype.

## 5. Sequence and exit criteria

1. **WS-F0, proposed:** review/implement/test only the fake-port construction, mapping and lifecycle slice after separate authorization; retain Phase1/SQLCipher artifacts unchanged.
2. **Diagnostic readiness:** reviewed noncreating original-state investigation and safe framework/reference-lifetime plan. No fresh native probe before this prerequisite is satisfied or explicitly reconsidered by its authorized owner.
3. **Native minimal slice:** separately approved new harness; WKS-001/005/006/007 and non-destructive private/group ownership controls first, with precise source/class identity. No default namespace.
4. **Lifecycle/deletion:** owner counts, late result/lock/shutdown/termination checks; then independently approved destructive new-store removal/failure cases. Confirm release/completion observation before cleanup claims.
5. **Backup/migration:** only after class capability and safe stage/removal handling; evaluate macOS26 localStorage candidate, unsupported types, failures and independent restore. No full archive/Keychain or SQLCipher PQR inference.
6. **Release platform qualification:** WKS-037 and all unchanged mandatory gates on the final candidate at the scheduled stage.

Exit is a per-case/class/platform capability report plus unresolved failures/blocks. It cannot close EXP-01/02/05/07 or AC08 as a whole without their full existing charters. Existing EXP-01 FAIL, EXP-02 INCONCLUSIVE, EXP-05/07 BLOCKED, cleanup crash and separate Phase3 49/49 and48/48 remain unchanged. All40 new cases are Proposed / Not Run. No runtime pass rate is created.

**No WebKit/Keychain runtime, SQLCipher/provider operations, database opens/creates, encrypted fixtures, builds or runtime tests were executed.**
