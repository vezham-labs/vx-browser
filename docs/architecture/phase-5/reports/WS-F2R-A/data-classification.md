# Data classification and protection

Proposed application-owned policy under current owner dispositions. **Required** means protect sensitive durable bytes, sidecars, derived data and intermediates against the stated threat, with authenticated identity at admission. A low global preference must pass a positive allowlist review. An omitted or new field defaults to protected until classified. “Backup” below refers to the portable Vezham archive. [Owner dispositions §29](../M1/m1-developer-specification.md), [data model](../M1/browser-core-data-model.md), [encryption specification](../M1/m1-persistent-profile-encryption-specification.md), [OP-01–04](../M1/m1-owner-decision-register.md)

Catalog bootstrap should expose only what is necessary to locate protected state. An opaque identifier can still be a correlation signal. If it must be visible, document and test the disclosure budget, authenticated binding and behavior when the bootstrap is missing or tampered. Keep keys and origins out of operational receipts.
