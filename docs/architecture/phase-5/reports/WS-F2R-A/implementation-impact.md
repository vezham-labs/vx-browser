## What changes and what stays

- **Can simplify:** Keep all website data out of owned storage and default portable archives; use one protected backend behind logical ports; use standard OS mechanisms for custody, files and consent; optionally use a tiny low global tier. Keep private and transient state out of persistent repositories.
- **Must preserve:** Owner requirements, engine-neutral Core, signed independent OS authority, encrypted profiles and sensitive catalog content, fenced keys and writes, typed failure paths, independently authorized file effects, offline recovery, versioned backups, historical evidence and current public/release restrictions.
- **Would require migration:** A real protected backend/schema/archive format change if authoritative inputs exist. No production data migration is implied by model or fixture evidence. Treat old stores and copies as potentially authoritative until examined with permission. SQLCipher-protected sources remain subject to D2A-01.
- **Needs new native qualification:** Success under real signed Keychain ACLs, required macOS lifecycle triggers and interruption, full persistent lock/unlock, native permission outcomes/revocation, supported cache and deletion effects, authorized downloads/resume, actual owned DB and backup/recovery, and the final-release environment.
