## Proposed WS-F2R exit criteria

- Latest native failure has an attributable result and corrected finite verification, or a precise remaining platform/environment blocker; no script-error/timeout relabeled denial.
- Every supported native permission path has grounded origin/frame/profile/OS/lifetime/cancellation evidence; unsupported paths remain disabled and explicitly classified. Device-positive tests require authorized consent/configuration.
- Available development lock/key paths are qualified with acquired-key controls where claimed; incomplete OS or durable/unlock guarantees remain blocked.
- Protected catalog is either genuinely integrated against an authorized qualified provider, or remains visibly blocked by the exact unresolved prerequisite. A refusal gate is not an implementation PASS.
- Backup improvements are labeled synthetic/contract versus actual source/import/custody; external files and unknown deletion lineage remain protected.
- New candidate evidence/checksums, source manifests, historical preservation and every affected WKS disposition are reviewable; final-release gates stay separate.
- Closeout states the exact remaining gaps. A bounded development closeout does not by itself complete WS-F2, approve the engine unconditionally or authorize release. If required WS-F2R acceptance is blocked, report that outcome honestly.
