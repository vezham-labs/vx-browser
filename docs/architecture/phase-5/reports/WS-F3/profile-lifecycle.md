# Profile lifecycle

Existing Core coordination and the native engine adapter still own store assignment, activation, switching, fencing, retirement and removal. The provider probe establishes a real fixed-identity read check for disposable fixtures. Product-level create, reopen, lookup, switch, lock and delete still lack the durable catalog/profile repositories and their authenticated coordination. A native WebKit fixture can use injected metadata ports, which does not establish actual persistent Vezham profile publication.

Required integration: tie durable binding and journals to the same authenticated lease and generation as the protected stores, recheck epoch before publication, fence missing/foreign inputs, and reconcile create/delete interruptions without creating replacements. Catalog, profile store, Keychain and WebKit effects need separate receipts.
