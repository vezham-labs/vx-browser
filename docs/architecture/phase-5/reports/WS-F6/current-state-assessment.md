## Existing architecture constraints

The engine contract keeps profile assignment immutable for a window or view and assigns its store before navigation. Platform architecture separates privileged bundled chrome, native policy and website content. The MVP gate explicitly exercises simultaneous windows for separate profiles and private mode. The one-main-workspace F6 fixture is a bounded development setup within these constraints. ## Evidence and tests

WS-F4R's two historical runs had 87 scoped native assertions each. WS-F5's final isolated candidate had 42 native and 13 contract assertions per launch across two launches, and 12 stand-in UI cases. WS-F5R execution-01 records 35 PASS_NATIVE observations of actual AppKit/WebKit, 9 PASS_CONTRACT including the injected callback trigger, and 14 PASS_FAKE_ONLY chrome cases. No actual OS helper termination or fresh Vezham test run is claimed by this package. The newer development host and the 26.0 minimum deployment target are different from real 26.0/latest 26.x runtime evidence.
