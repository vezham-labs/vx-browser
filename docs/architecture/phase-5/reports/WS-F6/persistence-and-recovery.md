Global appearance remains the existing low-sensitivity SQLite setting. Workspace names, graphs and geometry can disclose user activity and belong to the protected tier. A fail-closed profile/catalog path never falls back to unprotected SQLite or a default WebKit store. [WS-F3 architecture](../WS-F3/architecture-final.md)

## Publish one coherent revision

1. Load the source as an immutable candidate with version and size bounds. Decode known fields, validate structure, then normalize optional references and keep the original bytes and a redacted repair reason. Use the first catalog workspace if last selection is missing or stale within the library. Honor the existing authority before showing protected metadata.
2. Stage a whole normalized catalog/session revision under a single expected-revision replacement. F6 proves the contract against an in-memory port and a disposable fixture backend. Store both sections atomically. Product worker and filesystem techniques are decisions under the protected repository design.
3. Revalidate active authority/revision at the publication boundary. On failure or interruption before commit, expose the previously committed revision. On a lost response after commit, reconcile using operation identity and the authoritative revision under the current grant. Never resubmit blindly. Stale mounts cannot receive publication or authorize new writes. A lock or close cannot make a later completion revive the view or grant.
4. Future persistence backends must prove the same guarantees under disk full, locked/missing/wrong key, interrupted migration, profile deletion and concurrent save. Reopening a last-good checkpoint requires the same identity, version and authorization checks and an explicit recovery selection when the primary record is corrupt.

## Versioning, crash and repair

Define V1 as the first fixture schema. Use an explicit bounded synthetic V0 migration test for a graph with stable IDs, no split or geometry, and one ordered catalog and layout per workspace. V0 otherwise uses the same field shapes, order and required identities as V1. Migration copies IDs and ordering, sets `split` and `windowFrame` to null, validates V1 and writes a single new revision only under authorized compare-and-replace. It must be deterministic, repeatable and refuse an already changed source. V0 is a test vector and has no claimed production data or compatibility burden.

An older reader refuses future versions and leaves source bytes untouched. A malformed or structurally corrupt graph fails closed with a clear recovery state, no loads and no overwrite. User- or fixture-selected fallback may open a new empty volatile graph with no authority to overwrite the failed record. An optional missing selection, missing group or single surviving split member normalizes in memory. It is only saved with a later explicit valid transaction. Record the reason category without logging private names, URLs or raw snapshots. Keep a valid logical restore when eligible view construction fails. A restored slot can stay blank or unavailable without deleting its layout.

WS-F7 must establish production write authority with the exact approved D2A-01 Option 2 boundary and remaining provider/sidecar gates, signed positive Keychain lifecycle, authenticated profile binding, secure backup and rollback behavior. The bounded read-only probe establishes neither production custody nor write readiness. WS-F8 independently qualifies upgrade/rollback and signed release behavior on the supported OS matrix.
