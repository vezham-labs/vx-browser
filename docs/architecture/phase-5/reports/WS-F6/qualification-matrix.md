# Qualification matrix

**Implementation update · 10 November 2026.** This file retains the original 40 planned scenarios. Consult the implementation qualification ledger for actual results and missing permutations. Original NOT_EXECUTED planning entries are historical. [Implementation report](implementation-report.md) · [Actual qualification](implementation-qualification.md)

**Planning status:** Every proposed case is **NOT_EXECUTED** unless explicitly **BLOCKED**. All data and destinations are synthetic or owned fixtures. **C** means contract with deterministic fakes. **N** means real AppKit/WebKit is required, even with synthetic inputs. **N/C** means independently report the contract trigger and native effects. Follow the existing WS-F5R authority and case dispositions. No fault injection into real WebKit helpers without positive attribution and an authorized disposable candidate.

## Status and evidence

| Status         | Meaning                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| PASS_NATIVE    | Observed the stated behavior on the real native candidate. Never awarded for an injected trigger itself.   |
| PASS_CONTRACT  | Verified a policy, transition or intentionally injected event with deterministic controls.                 |
| PASS_FAKE_ONLY | Verified a chrome stand-in, mocked bridge or fake provider only. Useful regression evidence for its layer. |
| INCONCLUSIVE   | Executed, with an insufficient or ambiguous observation.                                                   |
| NOT_EXECUTED   | Planned, with no execution claim.                                                                          |
| BLOCKED        | A required prerequisite is absent. Record the dependency and safe stop condition.                          |
| FAIL           | Executed and violated the stated oracle. Preserve the failed attempt and exact reason.                     |

Evidence keys used in each row:

- **L** Redacted graph and command outcome before/after, revision and operation identity.
- **V** Adapter/Core event trace and owned inventory, scope/epoch, view IDs and attachment/retirement observations, or explicit zero-call trace for contract-only cases.
- **P** Synthetic store or fixture repository evidence, expected/observed revision, hashes and exclusion/no-write oracle. No user data or secret values in logs.
- **O** Owned origin request/commit correlation, observed load counts and controlled markers. Distinguish WebKit traffic from test scaffolding.
- **A** Native interaction witness, such as measured content frame, pointer sequence, first-responder/AX state or actual VoiceOver speech/captions. AX roles alone cannot satisfy the speech oracle.
- **H** Approved test process provenance, positive two-host discrimination, signal-time identity, callback match and process exit observation.

All case records must include exact candidate/source hash, test layer, environment and fixture versions, inputs, ordered actions, expected/observed results, and redacted artifacts. Native cases also record macOS/WebKit build, architecture, signing/entitlements and runner identity. Use a fresh evidence directory and record attempts without overwriting earlier artifacts. Historical qualification retains its original revision and category.

## Baseline blockers and stage separation

F6-36 remains blocked on safe helper attribution and the existing WS-F5R owner/test prerequisite. Native drag, VoiceOver speech or captions, successful downloads, external authentication and actual macOS 26 remain open in WS-F5R. Any portion of F6-22 or F6-24 lacking actual operator or supported runtime evidence keeps its own status. Native development-host results cannot replace F8 macOS 26.0/latest supported 26.x and signed artifact tests. Actual catalog write, key/lock/clear/delete, backup and migrations on protected user data belong to WS-F7.
