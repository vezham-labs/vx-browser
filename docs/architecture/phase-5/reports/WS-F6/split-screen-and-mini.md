# Split Screen and Vezham Mini

**Classification: PROPOSED.** Split represents an ongoing two-page task. Mini is a temporary private window for a link. Each uses the host's native window/layout controls and the existing engine authority.

## Split Screen

- **Ownership and order.** A pair is two distinct tab IDs in one Space, leading then trailing, with one focused member. A Space switch remembers the pair and makes only the destination Space eligible for new admission. Exit Split keeps both tab slots and selects the focused member. Removing or moving a member converts the survivor to a single tab. Cross-Space and cross-scope pair requests fail without a partial layout.
- **Focus.** The native responder and pane-selection controls update the logical focus through typed actions. Back, forward, reload, stop, address and page commands target the focused eligible pane only. The command bar and accessibility tree identify that pane. Returning from a panel or hiding a pane restores focus to a currently visible target or to browser chrome.
- **Divider and compact mode.** Use the current 600-point content-width threshold and 250-point native pane minima as the proposed fixture baseline. Apply the remembered basis-point ratio in the actual available divider geometry, clamped to each pane minimum. Save the user's completed divider change. Automatic resizing, clamping, restoration and compact presentation do not overwrite preference. Below threshold show the focused member, retain both logical members and provide a focus-other action. At threshold or above, reveal both and reapply the preference. If actual geometry cannot meet the minima, keep the compact presentation.
- **Partial restore and failures.** Invalid pair references normalize according to the model. A local clean construction failure shows a pane-local placeholder and retry with the other member still usable. If either pane poisons the scope, both affected surfaces become unavailable. No sibling remains interactive in the same poisoned scope.
- **Scope.** One remembered pair per Space. No third pane, nested split or cross-window live view reuse. Neither per-pane navigation state nor website data is a layout field.

## Mini lifecycle and isolation

Each Mini has a distinct private session, grant and nonpersistent WebKit store. It has no layout row, workspace sidebar or protected profile. It never silently inherits the main workspace's profile, store, cookies, logins, cache, service workers, history, passwords, grants, scripts, tab IDs, split state, back/forward list, form contents or view. Chrome appearance can use the existing global preference. Eligible external links still pass the existing route policy; this proposal adds no general URL-command capability. ## Destination and handoff

| Stage     | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Preview   | Show origin and eligible link, receiving workspace and Space, and whether the destination is private or an authorized normal profile. Offer handoff only to the currently mounted workspace's active Space. Preview alone makes no destination changes.                                                                                                                                                                                                                                                                              |
| Request   | On explicit confirmation, issue a single transfer operation bound to Mini's current committed main-frame identity and the destination's workspace, Space, mount generation and authority. A change to the source page or target context invalidates the preview.                                                                                                                                                                                                                                                                     |
| Validate  | Eligible candidate is a provenance-checked main-frame GET destination. First slice uses owned fixture URLs and the existing URL admission policy, excluding embedded credentials, fragments and queries. Rejection includes unknown provenance, POST, subframe, ineligible scheme, changed destination, busy/locked/fenced target or capacity. Keep Mini open and report the reason.                                                                                                                                                 |
| Accepted  | Receiver has reserved a fresh selected logical tab and issued a fresh authorized GET through its own WebKit binding. The native owner correlates operation, destination tab, view, mount generation and navigation in a volatile receipt. Acceptance publishes the logical slot in the active fixture state. An eventual protected save remains a separate authorized transaction. The request uses no source request headers, cookies, referrer, body, history or view. Its own receiver cookies apply normally. Mini remains open. |
| Committed | Observe the same request's main-frame commit in the expected current receiver, at the eligible requested URL. Compare canonical parsed URLs, including scheme, authority and path, under the same receiver policy. An error page, unrelated navigation, precommit failure, unexpected redirect or stale callback leaves Mini open. Commit is document arrival and is distinct from page completion or successful site login.                                                                                                         |
| Close     | After commit, recheck the active operation and Mini generation, then retire Mini independently and close it on confirmed cleanup. Manual close cancels source-side observation, retires independently and does not close a receiver tab already accepted. Cleanup uncertainty stays fenced and is surfaced to the owner.                                                                                                                                                                                                             |

Recheck source closure and operation validity immediately before the receiver issues the load. Serialize acceptance and source cancellation in the native coordinator. Cancellation or failure that wins before acceptance rolls back the staged destination slot and proves no abandoned binding. After acceptance, keep the destination slot as a visible result with its status if loading fails or times out. Do not retry automatically. A repeated confirmation for the same operation returns its receipt and creates no second tab. While that destination tab remains open, show it as the result and require a separate explicit new-tab action to open another. If the destination changes or closes after acceptance, leave Mini available and require new confirmation. Transfer never writes the private source.
