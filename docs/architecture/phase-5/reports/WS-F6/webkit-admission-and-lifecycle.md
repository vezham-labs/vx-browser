# WebKit admission and lifecycle

**Classification: PROPOSED.** The existing authority, store assignment, publication and poison fences remain mandatory. The new layer plans visible demand and binds logical tabs to native view IDs. [Current implementation](current-state-assessment.md) · [ADR 0007](../../../../decisions/0007-logical-tabs-and-webkit-admission.md)

## Admission preconditions

The AppKit host derives visible slots from the mounted workspace, active Space, native presentation visibility and available width. A selected blank slot is a browser-chrome placeholder with no native website view. A visible slot with explicit navigation intent or an eligible synthetic fixture destination may request admission. A future protected normal restore destination requires separately approved retention and replay policy. Selection, pinning, an inactive remembered pair, a hidden overlay, workspace enumeration and layout decoding confer no navigation authority.

1. Resolve the current mount generation and authorized scope. Record one in-flight operation for the logical slot before awaiting anything. Serialize new opens per scope because Core allows bounded pending operations. Coalesce repeated demand for the same slot. Each native object gets a fresh `ViewID`; a previous mount or epoch cannot be reused.
2. Check the slot is still eligible and visible, and the window, scope and authority are current. Route construction through Core and `NativeStorageSession.open`. Require verified store assignment before `WKWebView` creation. Treat a default store, unknown store or absent grant as a denial.
3. Core/native publication checks the existing scope/operation/epoch. The window then checks mount generation, ownership, visibility and demand again before exposing a binding or attaching. If superseded after the native open, keep it out of presentation and retire it through Core. A stale success may not start a load.
4. After attachment, recheck the same authority and current typed intent before issuing an eligible fresh navigation. Defer dependent work until the appropriate native receipt. Correlate main-frame navigation status by view, operation, mount generation and navigation identity. Ordinary website traffic in an already-live hidden view is distinct from new background loads initiated by workspace restore.
5. The two visible members of a wide split can each own a binding. Use a deterministic order beginning with focus. If the width or focus changes during admission, recompute demand and discard stale work. No native view can occupy two pane attachments.

## Lifecycle and failure

| State             | Allowed transition and invariant                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Blank or dormant  | Logical slot exists without a view. A valid visible demand moves to admitting. A hidden slot can change organization without constructing anything.                                                                            |
| Admitting         | One pending owner and operation. Verified result becomes attached if still demanded. Stale/failed resources enter retirement; an observed clean failure becomes an explicit local unavailable state.                           |
| Attached          | Exactly one native pane has this binding. Navigation/focus commands revalidate current ownership. Leaving visibility detaches or, during a workspace switch, retires it.                                                       |
| Detached live     | No pane owns the attachment; the scope still owns the view. Reattachment to the same live generation may preserve in-page state. Initial restore never constructs such a view.                                                 |
| Retiring          | Reject attach/navigation for that binding. Cancel dependent work, detach native references, then request Core closure and check inventory and release receipts. The new binding waits until retirement is confirmed.           |
| Failed locally    | A recoverable construction or load error can leave the rest of a split usable if scope health and cleanup are proven. A user may retry only when current authority and no outstanding view are verified.                       |
| Scope unavailable | On poison, retirement ambiguity or failed ownership cleanup, block affected scope acquisition and actions. Retain logical layout for presentation where authorized. Never revive the old scope or copy resources to a new one. |

Closing a dormant slot involves no native close. Closing the last native view in a private scope can retire the whole scope even if the fixture layout still has dormant slots. Retain only that synthetic logical graph. A later authorized demand can use a fresh scope after confirmed retirement and revocation. The product private-session end and recovery paths retain their current behavior until separately reviewed. [Core close](../../../../../qualification/webkit-storage-f0/Sources/BrowserCore/LifecycleCoordinator.swift#L217) · [Recovery policy](../WS-F5R/recovery-design/workspace-restoration-policy.md)

A content-process callback is a scope event under the existing poison fence, even if only one pane notified. Discard old navigation intents and ignore callbacks from stale identities. For product private recovery retain the WS-F5R path and its real-termination gate. In F6 fixtures, exercise local creation failure separately from injected scope poison and demonstrate blocked sibling use, isolated Mini continuity, and no replacement before confirmed retirement. An injected trigger is contract evidence. Real OS termination requires the existing attribution gate. ## Resource and navigation bounds

Use logical caps and visibility-derived demand before introducing eviction. Existing live views may remain detached and owned for in-session continuity. No automatic sleep/discard of live forms, media, calls, downloads or interactive state is planned. Under reported pressure stop any speculative work and measure current views, native inventory, helper footprint where attributable and close/reopen behavior. A bounded admission failure keeps UI and other healthy scopes usable. Do not use helper counts as proof of view identity or store isolation.

A reattached live view can keep its in-memory WebKit history. Restart, new scope, or retirement restores only the logical layout and starts blank. Never serialize or automatically replay a POST, a requested but uncommitted URL, a request body, redirect chain, cookie or page history.
