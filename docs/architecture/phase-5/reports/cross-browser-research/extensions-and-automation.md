# Extensions and automation

| Reference | Implementation or documented surface | Vezham relevance |
|---|---|---|
| Search | `WKWebExtension` host, CRX validation, compatibility shims, native messaging, browser/tab adapters, AppleScript read interface, opt-in bench socket and separate MCP test app | The native extension path exists, but each shim creates new behavior and permissions to own. The isolated MCP fixture is a better test reference than a user-session bridge |
| Arc/Little Arc and SigmaOS | Arc documents Chromium extensions and DevTools. Separate Little Arc extension/automation behavior is unverified. SigmaOS documents selected compatible extensions and settings. Its private implementation and coverage are unverified | Product documentation can inform UX and a compatibility ledger. Engine parity requires implementation-specific tests |
| Zen | Firefox WebExtensions integration and separate Zen Mods/browser style tooling | Add-on permissions and customization are separate. Gecko extension integration and CSS chrome are unsuitable as WebKit mechanisms |
| Cra and Stedding | Cra's CEF extension path differs from its WebKit media path, with documented `cra://` commands. Stedding uses Chromium extensions and DevTools | A URL command surface is an input boundary. Vezham's existing route can remain narrow and versionable. Chromium capabilities and native compatibility claims stay engine-specific |
| Flecha | Chromium native messaging host with MCP over IPv4 loopback, local Host checks and bearer auth. Tool schemas include reading, screenshots, input and page JavaScript | Source shows a significant production control surface. Loopback and a token reduce access but cannot settle per-window scope, local caller compromise, request approval, prompt injection, private data exposure or revocation |
| Refrax | Unix socket CLI with mode 0600, same-UID peer check, audit-token identity, persisted client access policy and engine-mediated control; WebKit extension handling | Shows real cost beyond transport. It requires identity, prompts, revocation and action policy. Do not infer that same UID confers trusted access |
| Vela | Electron extension subset, DevTools and Boosts. Vela publishes a project compatibility sample and API gaps | Use a per-extension API/permission matrix if a first-party WebKit pilot is ever justified |

## Public WebKit feasibility

A future extension investigation can use `WKWebExtensionController` with a scoped configuration and a small first-party/unpacked sample. The host must represent tabs/windows, mediate match patterns and grants, handle installation provenance and updates, and define background worker and profile lifecycle. Apple documents that extensions may access other open-tab stores subject to permissions. Test controller/store binding, default-store avoidance, private admission and revocation. Initially exclude private sessions, native messaging, cross-profile APIs and Chrome Store parity. A compatibility table should include manifest support, tabs and navigation, host permissions, storage, worker wake-up, downloads, request rules, OAuth and denied operations. Vezham's current production build has no extension controller in the audited composition. [Apple extension controller](https://developer.apple.com/documentation/webkit/wkwebextensioncontroller) · [Controller default-store behavior](https://developer.apple.com/documentation/webkit/wkwebextensioncontroller/configuration-swift.class/defaultwebsitedatastore) · [Search extension host](https://github.com/driceroland/Search/blob/e198e77b6e57519d6ceb0d13a816757dffa586ad/Sources/Search/Extensions.swift)

Apple's public Web Inspector opt-in is a narrower developer tool than remote CDP. Investigate a development-build-only opt-in for an explicit owned fixture view, with clear selection and separate teardown. Existing Vezham native runners and Playwright stand-ins offer the first qualification route. Playwright's bundled WebKit or bridge mock cannot stand in for the shipped macOS AppKit/WebKit host. [Apple inspection guide](https://developer.apple.com/documentation/safari-developer-tools/enabling-inspecting-content-in-your-apps) · [Vezham runner](../../../../../apps/browser-macos/Tools/wsf5r.py)

A later automation study could expose narrow, typed operations in a disposable, isolated test instance against owned loopback pages. Require caller identity, capability scope, input validation, expiry, revocation, and redacted evidence. Verify that private windows, cookies, credentials, arbitrary script or file access, native messaging and general command execution are unreachable. A product listener, arbitrary site scripting, broad remote debugging or agent control of user sessions is outside the recommended scope.
