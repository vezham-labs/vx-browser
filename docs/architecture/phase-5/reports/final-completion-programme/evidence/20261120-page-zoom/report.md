# Installed WebKit page zoom

Baseline was clean on cross-browser-research at 965663a. Arc 2 1.172.1 (90370) exposed Zoom In, Zoom Out and Zoom to Actual Size. The native View menu now adjusts the selected WKWebView from 50% to 300%, with reset to 100%. Availability follows the mounted view, recovery state and limits. Zoom belongs to the live WebKit view. No new persistent setting was added.

Two builds were installed. The second added window keyboard routing. A loopback fixture with a fixed-size rectangle demonstrated enlargement through the menu, minimum size via Command-minus, actual size via Command-0, and retention upon returning to the first tab. The first candidate showed default zoom in a second tab (155 rows versus 475 in the first). The final second-tab frame had zero measured fixture rows, so that frame is inconclusive. The Command-equals input did not produce observable enlargement in either run. Zoom-in keyboard acceptance remains open. measurements.txt reports decoded screenshot rows containing the rectangle's interior color. CSS viewport text did not distinguish page scale and was excluded as an acceptance metric.

Core 104, storage 27, legacy UI 16, navigation 4 passed. Workspace passed 39 native and 7 contract cases. Recovery passed 34 native and 11 contract cases. Typecheck, build and bundle audit passed. Workspace and recovery used a separate qualification build. These captures measure rendered Vezham page zoom only. The prior Arc 2 visual comparisons and drag witnesses belong to earlier binaries. Overall parity, protected restore and release qualification remain incomplete.
