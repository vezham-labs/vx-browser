# Security and recovery

The production ProtectedCatalog actor returns unavailable for profile reads, catalog mutations and journal writes. NativeStorageSession composes this actor at normal startup. Private windows use an in-memory profile authority and a separate nonpersistent WebKit store. No normal product workspace is routed through the fixture worker.

WS-F3 Option D keeps website data with WebKit and product records with the native protected provider. D2A-01 permits one 100-byte encrypted-header read in the pinned qualification path after the scoped key is present in worker memory. Production applicability is still unresolved. The existing worker uses authenticated read-only descriptors, disposable synthetic keys, encrypted in-memory SQLite updates, revision checks and synchronized staged publication to disposable files. Its qualification build guard and absence from Xcode linkage prevent admission as a production provider.

The native broker already uses SecRandomCopyBytes and the macOS data protection Keychain. Its user-presence policy, device-only unlocked accessibility and non-synchronizing records protect keys under the signed application's authorized access group. The broker uses its application's default group. The current ad-hoc build provides no verified signed application identity for positive custody. Release settings disable injection of base entitlements. Validate the actual signed application-identifier and any profile-authorized entitlements on a dedicated signed candidate before exercising real Keychain custody. No shared access-group string or profile was fabricated. [Apple macOS Keychain technical note](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) · [Apple provisioning profile guidance](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles)

Missing, denied or invalid custody must fence access while preserving encrypted state. A fresh key must be created only for an independently confirmed fresh profile. A missing key for an existing catalog needs an explicit recovery path through the original authorized key or an approved backup. Production restore must authenticate scope and schema before publishing state, validate the logical layout, retain dormant tab slots, and avoid replaying unapproved URLs. These product policies have no end-to-end evidence yet.

The workspace matrix distinguishes malformed ciphertext, interrupted staging, previous-revision recovery, CAS conflicts and Core layout version coverage from production browser recovery. Production catalog lifecycle and durable restore still require engineering in addition to credentials. [Workspace matrix](workspace-matrix.md)
