# Browser Testing and Evidence

ADR Stage A covers bounded selection evidence and risks; Stage B validates the actual implementation as it is built; Stage C qualifies a release candidate. These are timing stages, distinct from the preserved ledger's A/B/C/D requirement categories.

The separate Phase 3 49/49 recovery and 48/48 regression suites remain historical. Earlier performance does not qualify M0 or any later source revision. Do not rerun Phase 3 as a substitute for scoped M0 acceptance or merge new evidence into its directories.

M0 verification covers a native development build, bundle/protection audit, real launch/normal quit and documentation/source preservation. It is not an engine, bridge, account, privacy or release test. Record commands, exit codes, source SHA/dirty tree, OS/SDK/engine where relevant, outputs, limitations and blockers under a unique Phase 5 run. Retries need new information or a documented code/environment change. Account/media workflows remain blocked until separately authorized.
